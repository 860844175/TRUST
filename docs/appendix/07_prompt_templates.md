# Prompt Templates

<a id="tab:prompts"></a>
| **Task** | **Prompt Template** |
| :--- | :--- |
| **Vulnerability Identification** | **Task:**<br>Identify vulnerable code blocks within a given C function.<br>**Input:**<br>1. `Code Snippet` — the complete C function to be analyzed.<br>2. `Context` — a list of macro definitions or type declarations relevant to the function (optional).<br>**Output:**<br>A list of vulnerable code blocks, each formatted as follows:<br>&emsp;- **Code Block n**:<br>&emsp;&emsp;- **Function Name**: `<Function_Name>` (If not available, use `"N/A"`)<br>&emsp;&emsp;- **Code Snippet**: <br>&emsp;&emsp;&emsp;`<Code>`<br>&emsp;&emsp;- **Line Numbers**: [Start_Line - End_Line]<br>If no vulnerabilities are found, return: `"no vulnerability detected"`. |
| **Vulnerability Explanation** | **Task:**<br>For each identified vulnerable code block, provide a concise explanation of the root cause and potential impact.<br>**Input:**<br>1. `Code Snippet` — the full C function in which vulnerabilities have been detected.<br>2. `Identified Vulnerabilities` — a list of vulnerable code blocks, each including:<br>&emsp;- Function Name<br>&emsp;- Code Snippet<br>&emsp;- Line Numbers<br>3. `Context` — a list of relevant macro definitions, type declarations, or helper functions (optional).<br>**Output:**<br>For each vulnerable block, return a natural language explanation covering:<br>&emsp;- The root cause of the vulnerability<br>&emsp;- Its potential security or functional impact<br>If no vulnerabilities are provided, return: `"no vulnerability detected"`. |
| **Code Refinement** | **Task:**<br>Given a code snippet and its inspection result, generate corrected versions of each vulnerable code block that mitigate the described vulnerabilities while preserving functionality.<br>**Input:**<br>1. `Code Snippet` — the full source code containing the vulnerabilities.<br>2. `Inspection Result` — a structured output specifying vulnerable blocks, explanations, and line numbers.<br>3. `Context` — macro definitions or type declarations that may assist understanding.<br>**Output:**<br>For each code block, return the corrected version in the following format:<br>&emsp;- **Code Block n**:<br>&emsp;&emsp;- **Function Name**: `<Function_Name>`<br>&emsp;&emsp;- **Code Snippet**: <br>&emsp;&emsp;&emsp;`<Code>` |
| **Confidence Calibration** | **Task:**<br>Evaluate whether the inspection result and refined code snippet jointly meet the criteria for a trusted vulnerability fix.<br>**Input:**<br>1. `Code Snippet` — the original vulnerable code under inspection.<br>2. `Inspection Result` — a structured output identifying vulnerable blocks and their root causes.<br>3. `Refined Code Snippet` — the updated code intended to resolve the identified issues.<br>**Decision Rule:**<br>Output `HIGH` if:<br>&emsp;- The inspection result thoroughly identifies all critical vulnerabilities (locations and causes), and<br>&emsp;- The refined code snippet fully resolves the issues without introducing new risks.<br>Output `LOW` if:<br>&emsp;- The inspection result is incomplete or incorrect; or<br>&emsp;- The refined code fails to address the vulnerabilities or introduces new issues.<br>**Output:**<br>label: `HIGH` / `LOW` |

*Caption: Task-specific prompts used in the TRUST pipeline. Each prompt is designed to elicit structured outputs aligned with the corresponding code security task.*


Table above presents the carefully designed prompts used throughout both the fine-tuning and evaluation stages of the TRUST pipeline. Each prompt corresponds to a distinct task in our multi-step vulnerability assessment framework, including vulnerability identification, vulnerability explanation, code refinement, and confidence calibration.
